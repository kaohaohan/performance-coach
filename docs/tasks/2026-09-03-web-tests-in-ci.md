# Task: Run the web test suite in CI

- Date opened: 2026-09-03
- Related contract sections: AGENTS.md §17 (Verification Rules), §18 (Definition of Done), §7 (sizing), §9 (task docs)
- Size (S/M/L/XL, per AGENTS.md §7): **S**

Audited source of truth: `claude/performancecoa-chinese-switch-9n35mk` @ `bbbe520`.

Trigger: recorded as follow-up 3 of `docs/tasks/2026-08-27-i18n-zh-tw.md`.
The `web` job in `.github/workflows/ci.yml` runs `npm ci`, `npm run lint`,
`npm run build` and `npx tsc --noEmit` — and **no tests**. The repository has
136 `node:test` assertions across 12 files that have never run on a push.

## 1. Feasibility Analysis

- Problem / trigger: AGENTS.md §17 requires "relevant tests when they exist",
  and they exist. Because CI never runs them, two test files have been broken
  for an unknown length of time without anyone noticing, and the zh-TW
  localization work then broke them further — silently, since a test nobody
  runs cannot report a regression.

  Two distinct defects are hiding behind the same green build:

  1. **`app/coach/calendar/day-card.test.ts` and `duplicate-day-panel.test.ts`
     cannot be loaded.** Both call `renderToStaticMarkup` on a real component
     and import `./day-card.tsx` / `./duplicate-day-panel.tsx`. Node 22 strips
     TypeScript types but **cannot parse JSX**, so both fail immediately with
     `ERR_UNKNOWN_FILE_EXTENSION`. This predates the localization task.
  2. **Those same two tests now also fail for a second reason.** `day-card.tsx`
     and `duplicate-day-panel.tsx` call `useT()`, which throws
     `"useLocale/useT must be used within a LocaleProvider"` when the component
     is rendered outside the provider. The tests render it bare. This was
     introduced by sub-task 4 of the localization task and was invisible
     precisely because of defect 1.

  Defect 2 is the argument for this task: the cost of untested code is not
  hypothetical here, it already happened.

- Options considered:
  1. **Add `node --test` to CI and exclude the two broken files.**
  2. **Add a JSX-capable loader so every test runs, and fix the two files.**
  3. **Delete the two component tests** and rely on the pure-logic tests that
     already sit beside them (`build-transaction`, `workout-draft`,
     `duplicate-requests`, `exercise-creation`).
  4. **Move to a full test runner** (Vitest / Jest) with jsdom.

- Trade-offs (per option):
  1. Cheapest, and wrong. It writes "these two are allowed to be broken" into
     the build config, which is how they got into this state. It also would not
     have caught defect 2.
  2. One devDependency (`tsx`, esbuild-based) and a loader flag. Every existing
     test then runs unchanged except the two that need a provider wrapper.
     Keeps the repo on `node:test`, which the rest of the suite already uses.
  3. Loses real coverage: these two assert on rendered markup (status pills per
     assignment, the absence of an S/R footer), which the pure-logic tests do
     not cover. Deleting a test to make a build green is not on the table.
  4. Correct destination if the app ever needs DOM interaction tests, but a
     large change to install a second runner alongside `node:test` for two
     files. Not justified by this task's problem.

- Selected option and why: **Option 2.** It is the smallest change that makes
  the whole suite actually run, and it removes the condition that let defect 2
  hide rather than working around it (AGENTS.md §22).

- Risks & unknowns:
  - **The two tests' assertions may no longer match the rendered markup.** Both
    assert on English strings that now come from the message catalog, and
    sub-tasks 2c/3/4 changed some of that copy (for example `athlete` →
    `client`). `LocaleProvider` starts at `DEFAULT_LOCALE` (`en`) and its
    locale-detection effect does not run under `renderToStaticMarkup`, so the
    markup will be English — but not necessarily the *same* English.
    **Updating an assertion because the copy legitimately changed is correct;
    changing one to paper over a rendering difference is not.** If markup
    differs in a way that is not a copy change, stop and report it.
  - Adding a CI step makes previously-invisible failures visible. That is the
    point, but it means the first CI run on this branch may go red for reasons
    unrelated to this change. Every failure must be understood, not silenced.
  - `tsx` is an extra devDependency. It is dev-only and never ships.

- Dependencies / blockers: none.

## 2. Technical Design

### Affected files

| File | Change |
| --- | --- |
| `apps/web/package.json` | add `tsx` devDependency; add a `test` script |
| `apps/web/package-lock.json` | regenerated by npm — do not hand-edit |
| `apps/web/app/coach/calendar/day-card.test.ts` | wrap the rendered component in `LocaleProvider` |
| `apps/web/app/coach/calendar/duplicate-day-panel.test.ts` | same |
| `.github/workflows/ci.yml` | add a test step to the `web` job |

### Verified approach

Both halves were confirmed to work on this branch before this doc was written:

- `node --import tsx --test <file>` loads a `.test.ts` that imports a `.tsx`
  component — the `ERR_UNKNOWN_FILE_EXTENSION` is gone.
- Wrapping the component in `LocaleProvider` renders successfully
  (`React.createElement(LocaleProvider, null, React.createElement(DayCard, …))`
  produced 1246 characters of markup).

Note the tests must be run from `apps/web/`, not by absolute path from
elsewhere, or module resolution fails.

### CI step placement

Put the test step **after** `npm run build`. `next build` generates
`.next/types`, which the existing Typecheck step depends on (there is already a
comment in `ci.yml` explaining this); keeping tests after the build avoids
adding a second ordering constraint to reason about.

### package.json script

Add a `test` script so a contributor runs the same command CI does, rather than
CI having a bespoke invocation. Confirm which form actually discovers every
test file — Node's default discovery ignores `node_modules` — and use that same
form in `ci.yml` via `npm test`.

The suite currently spans `lib/*.test.ts`, `lib/i18n/*.test.ts`,
`app/coach/calendar/*.test.ts` and `app/coach/workouts/history.test.ts`.
All 12 files must run; state the count in the completion report.
